# 소프트웨어 요구사항 명세서 (SRS)
## 수조 수질 탁도 감지 및 텔레그램 즉시 알림 서비스

---

## 1. 서론 (Introduction)

### 1.1 목적 (Purpose)

본 문서는 수조 수질 탁도를 감지하고 이상 발생 시 텔레그램으로 즉시 알림을 전송하는 서비스 개발을 위한 요구사항을 정의한다.
개발자가 시스템을 설계·구현·테스트하는 과정에서 참조한다.

### 1.2 범위 (Scope)

- **사용자:** 가정용 어항 사용자부터 양식장·수족관 전문 운영자까지 수조를 관리하는 모든 사람
- **기능:** 탁도 더미 데이터 생성, 서버 수신 및 임계값 판단, 텔레그램 알림 전송, 이력 저장 및 조회
- **목표:** 수질 이상을 실시간으로 감지하여 관리자가 빠르게 대응할 수 있도록 한다

### 1.3 정의 및 약어 (Definitions, Acronyms, Abbreviations)

| 용어 | 설명 |
|-----|------|
| NTU | Nephelometric Turbidity Unit — 탁도 측정 단위 |
| 탁도 | 물의 탁함 정도. NTU 값이 높을수록 물이 더 탁함 |
| signal.py | 아두이노 하드웨어를 대역하는 더미 데이터 생성 스크립트 |
| 텔레그램 봇 | Telegram Bot API를 통해 메시지를 전송/수신하는 자동화 계정 |
| RTM | Requirements Traceability Matrix — 요구사항 추적성 매트릭스 |
| API | Application Programming Interface |
| SRS | Software Requirements Specification |

## 2. 전체 설명 (Overall Description)

### 2.1 제품 관점 (Product Perspective)

본 시스템은 실제 하드웨어(아두이노) 없이 동작하는 프로토타입으로, `signal.py`가 아두이노 역할을 대역한다.
로컬 환경에서 실행되며, 텔레그램 봇을 통해 알림과 조회 기능을 제공한다.

**시스템 흐름:**
```
signal.py (더미 탁도 데이터 생성)
    ↓ HTTP POST — 이상 감지 시에만 전송
FastAPI 서버 (데이터 수신 + 임계값 판단 + DB 저장)
    ↓ Telegram Bot API
텔레그램 봇 (알림 전송 + 명령어 응답)
```

### 2.2 제품 기능 요약 (Product Functions)

- 탁도 더미 데이터 생성 및 서버 전송 (signal.py)
- 탁도 임계값 판단 및 경고 수준 분류 (서버)
- 텔레그램 알림 자동 전송 (주의 / 위험)
- 이상 감지 이력 DB 저장
- 텔레그램 봇 명령어를 통한 최근 측정값 및 이력 조회

### 2.3 사용자 특성 (User Characteristics)

| 사용자 유형 | 특성 |
|-----------|------|
| 일반 사용자 (가정) | IT 지식 낮음, 텔레그램 앱만 있으면 사용 가능 |
| 전문 운영자 (양식장·수족관) | 다수 수조 관리, 빠른 대응 필요 |

### 2.4 제약 조건 (Constraints)

- 실제 아두이노 하드웨어는 구현하지 않음 (MVP 범위 외)
- 측정 항목은 탁도(NTU) 단일 항목으로 제한
- 알림 채널은 텔레그램 봇 단일 채널
- 임계값은 MVP에서 고정값 사용 (NTU 10 주의, NTU 50 위험)
- 운영 환경: 로컬 실행 기준

### 2.5 가정 및 의존성 (Assumptions and Dependencies)

- `signal.py`는 이상 감지 시에만 서버로 데이터를 전송한다고 가정
- 텔레그램 봇 토큰 및 채팅방 ID는 사전에 발급·설정되어 있다고 가정
- 네트워크 연결이 안정적일 것을 가정
- DB는 SQLite를 사용 (별도 설치 불필요)

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 더미 데이터 생성 (signal.py)

| ID | 요구사항 설명 | 우선순위 | 비고 |
|----|------------|---------|------|
| FR-01 | signal.py는 탁도(NTU) 값을 랜덤으로 생성한다 | Must | 생성 범위: 0~100 NTU |
| FR-02 | 생성된 NTU 값이 임계값(10 NTU) 이상일 경우에만 서버로 HTTP POST 요청을 전송한다 | Must | 정상 범위는 전송 안 함 |
| FR-03 | 전송 데이터에는 NTU 값, 타임스탬프, 장치 ID가 포함된다 | Must | JSON 형식 |

### 3.2 서버 (FastAPI)

| ID | 요구사항 설명 | 우선순위 | 비고 |
|----|------------|---------|------|
| FR-04 | 서버는 탁도 데이터를 수신하는 엔드포인트를 제공한다 | Must | POST /sensor/data |
| FR-05 | 수신된 데이터를 DB에 저장한다 | Must | 타임스탬프 포함 |
| FR-06 | NTU ≥ 10 이면 텔레그램으로 "⚠️ 주의" 알림을 전송한다 | Must | - |
| FR-07 | NTU ≥ 50 이면 텔레그램으로 "🚨 위험" 알림을 전송한다 | Must | FR-06보다 우선 |
| FR-08 | DB 저장 실패 시에도 텔레그램 알림은 계속 전송한다 | Must | 저장 실패가 알림을 막지 않음 |

### 3.3 텔레그램 봇

| ID | 요구사항 설명 | 우선순위 | 비고 |
|----|------------|---------|------|
| FR-09 | 이상 감지 시 지정된 채팅방에 알림 메시지를 자동 전송한다 | Must | - |
| FR-10 | 알림 메시지에는 감지 시각, NTU 값, 경고 수준이 포함된다 | Must | - |
| FR-11 | `/status` 명령어 입력 시 가장 최근 측정값을 반환한다 | Must | - |
| FR-12 | `/history` 명령어 입력 시 최근 10건의 이상 감지 기록을 반환한다 | Should | - |

## 5. 외부 인터페이스 요구사항

### 5.1 사용자 인터페이스 (UI/UX)

- 별도 웹/앱 UI 없음
- 텔레그램 앱을 통해 알림 수신 및 명령어 입력으로 조회

**텔레그램 메시지 형식:**

주의 알림:
```
⚠️ [주의] 수질 이상 감지
• 탁도: 15.3 NTU
• 감지 시각: 2026-06-29 14:32:05
• 장치: tank-001
```

위험 알림:
```
🚨 [위험] 수질 이상 감지
• 탁도: 63.7 NTU
• 감지 시각: 2026-06-29 14:32:05
• 장치: tank-001
```

### 5.2 하드웨어 인터페이스

- 실제 하드웨어 없음 (MVP)
- `signal.py`가 아두이노 역할을 소프트웨어로 대역

### 5.3 소프트웨어 인터페이스

| 구성 요소 | 기술 |
|---------|------|
| 서버 프레임워크 | Python + FastAPI |
| 데이터베이스 | SQLite |
| 알림 채널 | Telegram Bot API |
| 데이터 형식 | JSON (REST API) |

**API 엔드포인트:**

| 메서드 | 경로 | 설명 |
|-------|------|------|
| POST | /sensor/data | 탁도 데이터 수신 |

**요청 예시:**
```json
{
  "device_id": "tank-001",
  "ntu": 63.7,
  "timestamp": "2026-06-29T14:32:05"
}
```

### 5.4 통신 인터페이스

- signal.py → 서버: HTTP (로컬 환경)
- 서버 → 텔레그램: HTTPS (Telegram Bot API)

## 6. 시스템 아키텍처 개요

```
[signal.py]
    | 이상 감지 시 HTTP POST /sensor/data
    ↓
[FastAPI 서버]
    | 임계값 판단
    |── [SQLite DB] ← 이상 데이터 저장
    |
    | Telegram Bot API (HTTPS)
    ↓
[텔레그램 봇]
    |── 자동 알림 전송 (주의/위험)
    └── 명령어 응답 (/status, /history)
```

## 7. 요구사항 추적성 매트릭스 (RTM)

| 요구사항 ID | 테스트 케이스 ID | 설명 |
|-----------|--------------|------|
| FR-01 | TC-01 | signal.py가 0~100 NTU 범위의 값을 생성하는지 확인 |
| FR-02 | TC-02 | NTU < 10 이면 서버로 전송하지 않는지 확인 |
| FR-02 | TC-03 | NTU ≥ 10 이면 서버로 전송하는지 확인 |
| FR-06 | TC-04 | NTU 10~49 수신 시 "주의" 텔레그램 알림 수신 확인 |
| FR-07 | TC-05 | NTU ≥ 50 수신 시 "위험" 텔레그램 알림 수신 확인 |
| FR-08 | TC-06 | DB 저장 실패 시에도 알림 전송 여부 확인 |
| FR-11 | TC-07 | `/status` 명령어 응답 정상 동작 확인 |
| FR-12 | TC-08 | `/history` 명령어 최근 10건 반환 확인 |
| NFR-01 | TC-09 | 데이터 수신부터 텔레그램 알림까지 3초 이내 확인 |
